# Preguntas para Reunión con DGEMS

Este documento concentra las decisiones ya confirmadas y las dudas que conviene resolver con administradores DGEMS antes de iniciar desarrollo fuerte.

## Decisiones confirmadas

- Nombre oficial: SIGI-POA DGEMS.
- Nombre interno del equipo: ADPeak.
- Ciclo inicial: POA 2026.
- Alcance temporal: debe quedar preparado para futuros años.
- Primera demo funcional: 31 de mayo de 2026.
- Autoridad funcional esperada: Administrador DGEMS.

## Prioridad 1: alcance de la demo

- ¿Qué debe verse funcionando el 31 de mayo de 2026 para considerar exitosa la demo?
- ¿La demo debe usar datos reales controlados, datos anonimizados o datos ficticios?
- ¿Qué flujo debe estar completo para la demo: captura, evidencia, revisión, dashboard o reportes?
- ¿Qué funcionalidades pueden esperar para una segunda versión?
- ¿Quién revisará y aprobará formalmente la demo?

## Prioridad 2: usuarios y permisos

- ¿Cuántos planteles participarán en el ciclo inicial?
- ¿Cuántos usuarios tendrá cada plantel?
- ¿Qué roles oficiales deben existir además de plantel, responsable y administrador?
- ¿Un usuario puede tener más de un rol?
- ¿Un usuario puede pertenecer a más de un plantel?
- ¿Un responsable puede revisar todos los planteles o solo indicadores asignados?
- ¿El Administrador DGEMS puede editar capturas de planteles o solo administrar catálogos y revisar?
- ¿Quién autoriza altas, bajas y cambios de permisos?

## Prioridad 3: flujo de captura y revisión

- ¿Cuál es el flujo oficial de estados?
- ¿Puede un plantel editar una captura después de enviarla?
- ¿Quién puede devolver una captura con observaciones?
- ¿Las observaciones se hacen por campo, por evidencia o por captura completa?
- ¿Qué pasa si un plantel no entrega dentro del periodo?
- ¿Se debe bloquear la edición después de aprobar o cerrar un periodo?
- ¿Se necesita historial de versiones para cada captura?

## Prioridad 4: indicadores y formularios

- ¿El libro maestro revisado será la fuente oficial inicial de indicadores, responsables y actividades?
- ¿Los 99 registros de actividades y 48 indicadores únicos son definitivos para el ciclo 2026?
- ¿Cada indicador tendrá un formulario propio o se espera un sistema de formularios configurables?
- ¿Quién define campos obligatorios, validaciones y evidencia requerida por indicador?
- ¿Qué pasa si un indicador cambia durante el año?
- ¿Los responsables pueden crear o modificar indicadores o solo el Administrador DGEMS?
- ¿Se debe conservar el histórico de cambios en indicadores y actividades?

## Prioridad 5: periodos y ciclos anuales

- ¿Qué periodos se usarán oficialmente: quincenal, mensual, bimestral, semestral u otros?
- ¿Todos los indicadores usan los mismos periodos?
- ¿Quién abre y cierra periodos de captura?
- ¿Se pueden reabrir periodos cerrados?
- ¿Cómo se clonará o configurará un nuevo ciclo anual después de 2026?
- ¿Los indicadores de años futuros pueden cambiar completamente o se espera continuidad?

## Prioridad 6: evidencias

- ¿Qué tipos de archivo serán permitidos?
- ¿Cuál será el tamaño máximo por archivo y por captura?
- ¿Cuántas evidencias puede subir un plantel por actividad?
- ¿Las evidencias se pueden reemplazar o deben conservarse como versiones?
- ¿Quién puede ver y descargar evidencias?
- ¿Se deben registrar descargas de evidencia en una bitácora?
- ¿Qué documentos nunca deben subirse por contener datos personales sensibles?
- ¿Cuánto tiempo deben conservarse las evidencias?

## Prioridad 7: reportes y dashboard

- ¿Qué reportes oficiales necesita DGEMS?
- ¿Los reportes deben exportarse en PDF, Excel o ambos?
- ¿Qué filtros son obligatorios: año, periodo, plantel, indicador, actividad, responsable y estado?
- ¿Qué métricas son más importantes: avance, faltantes, observados, aprobados o atrasados?
- ¿Los responsables necesitan reportes distintos a los administradores?
- ¿Se requiere un reporte final consolidado del ciclo anual?
- ¿Hay un formato institucional que los reportes deban respetar?

## Prioridad 8: seguridad y datos personales

- ¿Qué datos personales se manejarán dentro del sistema?
- ¿Se guardarán nombres de estudiantes, números de cuenta, resultados de admisión o constancias?
- ¿Existe una política institucional de privacidad o aviso de tratamiento de datos que debamos seguir?
- ¿Se requiere autenticación institucional, correo UCOL, Microsoft, Google o usuario y contraseña propio?
- ¿Se necesita doble factor de autenticación?
- ¿Qué eventos deben quedar en bitácora?
- ¿Quién puede auditar accesos, cambios, aprobaciones y descargas?

## Prioridad 9: infraestructura y operación

- ¿Dónde se alojará el sistema: servidor institucional, nube o proveedor externo?
- ¿Quién administrará base de datos, respaldos y despliegues?
- ¿Hay stack tecnológico obligatorio o recomendado por la institución?
- ¿El sistema debe ser accesible desde internet o solo desde red institucional?
- ¿Quién dará soporte a planteles durante operación?
- ¿Quién cargará los catálogos iniciales?
- ¿Se necesita manual de usuario o capacitación formal?

## Preguntas de cierre

- ¿Cuáles son las tres funcionalidades indispensables para la primera versión?
- ¿Qué información no debe estar jamás dentro del sistema?
- ¿Quién será el contacto funcional para responder dudas durante el desarrollo?
- ¿Cada cuánto se revisará avance con DGEMS?
- ¿Qué criterio se usará para aceptar o rechazar cambios de alcance?
